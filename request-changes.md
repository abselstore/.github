# How to Request Changes to Repository Contents

Anyone can view the contents of a public repository, but only those logged into a GitHub account can initiate a standard change process that proceeds from creating a _fork_, then a _branch_, followed by a _pull request_. A _fork_ creates a copy of the targeted repository and connects an account to the repository, a _branch_ packages the requested changes, and a _pull request_ asks repository collaborators to review, approve, and act on the requested changes. The repository's creator has a primary connection to the targeted repository, so the creator can bypass the standard change process, which consists of the following steps:

1. From the [ABSEL Store](https://github.com/abselstore), click the **Repositories** menu item and click to select the repository targeted for the change. When the repository page appears, click the selector of the **Fork** button on the row immediately below the menu items to choose between using a previously created fork and creating a new fork. Choice made, the advisory message, _forked from..._ appears leftmost on the row immediately below the button.

2. To propose edits to a file, click the name of the desired file from the list of files shown, followed by clicking the pencil icon on the upper right end of the menu above the content-display area. Then with the **Edit** tab selected, use the computer's keyboard to edit the contents. If the name of the file ends with the _md_ extension, the file is Markdown-formatted, and a Markdown icon appears on the bottom right of the edit area. Click the Markdown icon for instructions on writing Markdown-formatted text.  

3. To propose adding files, click the **Add file** or **+** button on row above the list of files and select either _Create new file_ or _Upload files_. Follow the instructions that appear. If adding a text file, consider that GitHub works best with files in [Markdown format](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax), a formatting language for text that is easy to learn, to type, and to read. Moreover, files in Microsoft's Word (docx) format can be automatically converted to Markdown by free converters, such as [word2markdown](https://word2md.com/). Thus, when entering a name for a new file, specifying the _md_ extension (for example, `myfile.md`) causes GitHub to treat the file as a Markdown-formatted file.

4. Click the **Commit changes** button. The default option to _commit directly to the main branch_ packages the changes in a branch called `main`, after which other related changes might be similarly made and committed to `main` before selecting the **Pull request** menu item to send a pull request to repository collaborators. The alternative option of _creating a new branch and starting a pull request_ allows each set of changes to be packaged into its own named branch, each branch sent to repository collaborators by a different pull request. The alternative option is useful when the collaborators should review all sets before reaching a decision.

5. The final pull-request page, _Open a pull request_, contains edit boxes for entering the title and description of the request, accompanied by a **Create pull request** button with the selectable **Create draft pull request** alternative. Selecting the alternative holds the pull request until the **Ready for review** button is selected, perhaps later, after additional changes are included.

6. Pull request sent, the conditions for reviewing and merging, that is, executing the requested action, appears. The changes proposed can be acted upon either automatically when the conditions are satisfied, or at the discretion of repository collaborators, who may dismiss the request or execute it, that is, to _merge_ the branch to the _main_, after which the pull request is closed.
